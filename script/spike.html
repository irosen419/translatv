3. Echo test

Play Spanish audio out of your speakers (not headphones) with an en-US recognizer running. If transcripts appear while you are silent, echo leaks into recognition and the RMS gate below is required. Then repeat wearing headphones.

The Spanish below is spoken by the browser's own speech synthesizer rather than a downloaded recording. That keeps this page standalone and offline, which is the property that lets it run from a file:// URL with no server, and it means the script is KNOWN: whatever the recognizer reports while you are silent can be compared against what was actually said. If you would rather use a real human recording, load one with the file picker.
Read this before trusting a leak you see here. Synthesized speech and a local audio file both play as ORDINARY SYSTEM AUDIO, which the WebRTC echo canceller may not have in its reference signal. A real caller's voice does not arrive that way: it comes out of the peer connection's own playback, which the canceller does know about. So a leak measured here is an UPPER BOUND and may be far worse than a real call. It is still worth measuring, because it proves the microphone hears the speakers at all, but it does not settle whether a real peer leaks. Settling that needs a second device in a real call, which is why the matrix in vt-0004 asks for one.

6. Finalization latency

How long after you stop talking does a FINAL result arrive? This is the one stage of the pipeline that cannot be measured in a container, and docs/proposals/vt-0014.md found it is the largest remaining unknown: everything else between a spoken sentence and a rendered translation is about 11ms, so if this number is large then recognition dominates and swapping the translation model would not help.

Two measures, and they bracket the answer from BELOW rather than from both sides. Last interim to final is automatic and has no human in it, but it starts from the last time the engine reported hearing something rather than from the moment you stopped, so it is the smaller of the two. Marked speech end to final is closer to the real gap, and it is still an underestimate: clicking late moves the start of the interval forward, which makes the measured gap SHORTER, not longer. Add your reaction time, roughly 200 to 300ms, to get the honest figure. The true speech end to final time is at least the marked number.
